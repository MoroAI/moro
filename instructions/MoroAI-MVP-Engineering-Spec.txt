MoroAI MVP Engineering Spec**.

This is written as a practical spec you could hand to an engineer and start building immediately.

# MoroAI MVP Engineering Spec

## Spec Status
**Version:** v0.1
**Scope:** MVP only
**Target:** local-first CLI
**Primary language:** Python 3.10+
**CLI name:** `moro`
**Fallback CLI name:** `moroai`

---

# 1. MVP Objective

Build the smallest version of MoroAI that allows a user to:

```text
create a project
→ import data
→ build a clean dataset
→ detect hardware
→ suggest a safe training recipe
→ fine-tune a small open model locally
→ evaluate it
→ export it
→ deploy it to Ollama/GGUF-style artifact output
```

This MVP should be:
- local-first
- reproducible
- config-driven
- simple to install
- safe for low-VRAM hardware
- easy to extend later

---

# 2. MVP Non-Goals

For this MVP, we are **not** building:

- web dashboard
- multi-user server
- cloud sync
- custom training engine
- layer streaming
- distributed training
- plugin marketplace
- DPO/ORPO
- advanced synthetic data generation

Those come later.

# 5. Exact CLI Command Specification

Below is the exact MVP CLI surface.

---

## 5.1 `moro init`

### Purpose
Create a new MoroAI project.

### Command
```bash
moro init [PATH]
```

### Options
```text
--template [minimal|support|chat]   Default: minimal
--force                             Overwrite if project exists
```

### Behavior
Creates:
- `moro.yaml`
- `README.md`
- `.gitignore`
- `data/raw/`
- `eval/support-golden-v1.yaml`
- `.moro/`

### Exit codes
- `0`: success
- `1`: project already exists without `--force`

---

## 5.2 `moro status`

### Purpose
Show current project status.

### Command
```bash
moro status
```

### Options
```text
--json
```

### Output
Shows:
- project name
- config validity
- dataset source present or not
- latest dataset version
- latest run
- latest release

---

## 5.3 `moro doctor`

### Purpose
Check environment and hardware readiness.

### Command
```bash
moro doctor
```

### Options
```text
--json
```

### Checks
- Python version
- MoroAI installed
- PyTorch installed
- CUDA available
- GPU name
- VRAM
- CPU RAM
- disk space
- recommended model sizes
- missing optional dependencies

### Exit codes
- `0`: usable environment
- `3`: missing critical dependency

---

## 5.4 `moro import`

### Purpose
Import raw dataset files into the project.

### Command
```bash
moro import SOURCE
```

### Options
```text
--name TEXT                 Dataset source name
--format [auto|jsonl|csv|txt|markdown]   Default: auto
--copy / --link             Default: copy
```

### Behavior
- copies or links source into `data/raw/`
- registers dataset source in SQLite
- computes source hash

- `data/splits/train.jsonl`

## 6.1 Config Models

```python
from __future__ import annotations

from pathlib import Path
from typing import Any, Literal, Union

from pydantic import BaseModel, Field, field_validator


class ProjectConfig(BaseModel):
    name: str = Field(..., min_length=1, max_length=128)
    privacy_mode: Literal["local_only", "allow_external"] = "local_only"
    seed: int = Field(default=42, ge=0)


class DatasetConfig(BaseModel):
    source: Path
    format: Literal["auto", "jsonl", "csv", "txt", "markdown"] = "auto"
    deduplicate: bool = True
    pii_scan: bool = False
    max_seq_length: int = Field(default=1024, ge=16, le=32768)
    min_quality_score: float = Field(default=0.0, ge=0.0, le=1.0)
    validation_ratio: float = Field(default=0.1, ge=0.0, le=0.5)
    eval_ratio: float = Field(default=0.1, ge=0.0, le=0.5)

    @field_validator("source")
    @classmethod
    def validate_source(cls, v: Path) -> Path:
        if not v:
            raise ValueError("dataset.source is required")
        return v


class ModelConfig(BaseModel):
    name: str
    revision: str | None = None
    quantization: Literal["none", "int8", "nf4"] = "nf4"
    trust_remote_code: bool = False


class AdapterConfig(BaseModel):
    type: Literal["lora"] = "lora"
    r: int = Field(default=16, ge=1, le=256)
    alpha: int = Field(default=32, ge=1, le=512)
    dropout: float = Field(default=0.05, ge=0.0, le=1.0)
    target_modules: Union[Literal["auto"], list[str]] = "auto"
    bias: Literal["none", "all", "lora_only"] = "none"


class TrainingConfig(BaseModel):
    output_dir: Path = Path("runs")
    batch_size: int = Field(default=1, ge=1)
    gradient_accumulation_steps: int = Field(default=16, ge=1)
    learning_rate: float = Field(default=2e-4, gt=0)
    optimizer: Literal[
        "adamw_torch",
        "adamw_8bit",
        "paged_adamw_8bit",
    ] = "paged_adamw_8bit"
    gradient_checkpointing: bool = True
    precision: Literal["auto", "bf16", "fp16", "fp32"] = "auto"
    epochs: float = Field(default=1.0, gt=0)
    max_steps: int | None = None
    warmup_ratio: float = Field(default=0.03, ge=0.0, le=1.0)
    logging_steps: int = Field(default=10, ge=1)
    save_steps: int = Field(default=100, ge=1)

    @field_validator("output_dir")
    @classmethod
    def validate_output_dir(cls, v: Path) -> Path:
        return Path(v)


class EvalSuiteRef(BaseModel):
    path: Path
    name: str | None = None


class EvalConfig(BaseModel):
    suites: list[EvalSuiteRef] = Field(default_factory=list)
    base_model: str | None = None
    max_samples: int | None = Field(default=None, ge=1)


class ReleaseRequirements(BaseModel):
    eval_suite: str | None = None
    min_improvement: float | None = None
    max_regression: float | None = None
    safety_pass: bool = True


class ReleaseConfig(BaseModel):
    export: list[Literal["adapter", "merged", "gguf", "ollama"]] = Field(
        default_factory=lambda: ["adapter", "ollama"]
    )
    require: ReleaseRequirements | None = None


class MoroConfig(BaseModel):
    project: ProjectConfig
    dataset: DatasetConfig
    model: ModelConfig
    adapter: AdapterConfig = Field(default_factory=AdapterConfig)
    training: TrainingConfig = Field(default_factory=TrainingConfig)
    eval: EvalConfig = Field(default_factory=EvalConfig)
    release: ReleaseConfig = Field(default_factory=ReleaseConfig)

    @field_validator("project", "dataset", "model")
    @classmethod
    def required_sections(cls, v: Any) -> Any:
        if v is None:
            raise ValueError("required config section missing")
        return v
```

```sql
CREATE TABLE IF NOT EXISTS dataset_sources (
```

```sql
CREATE TABLE IF NOT EXISTS dataset_versions (
  id TEXT PRIMARY KEY,
  project_id TEXT NOT NULL,
  source_id TEXT NOT NULL,
  version TEXT NOT NULL,
  normalized_path TEXT NOT NULL,
  stats_json TEXT NOT NULL,
  created_at TEXT NOT NULL

```

```sql
CREATE TABLE IF NOT EXISTS runs (
  id TEXT PRIMARY KEY,
  project_id TEXT NOT NULL,
  dataset_version_id TEXT,

  status TEXT NOT NULL,
  config_hash TEXT NOT NULL,
  model_name TEXT NOT NULL,
  quantization TEXT NOT NULL,

  validation_loss REAL,
```

```sql
CREATE TABLE IF NOT EXISTS eval_runs (
  id TEXT PRIMARY KEY,

  created_at TEXT NOT NULL,
  total_cases INTEGER NOT NULL,
```

### `artifacts`
```sql
CREATE TABLE IF NOT EXISTS artifacts (
  id TEXT PRIMARY KEY,

  path TEXT NOT NULL,
  sha256 TEXT,
  size_bytes INTEGER,
  created_at TEXT NOT NULL
```

# 10. Exact CLI Standards

## Exit codes
- `0` = success
- `1` = generic error
- `2` = config/validation error
- `3` = missing dependency
- `4` = training failure
- `5` = dataset error

## Output conventions
- Human-readable table by default
- `--json` for machine-readable output
- Errors go to stderr
- Warnings do not fail command unless critical

## IDs
Use these formats:

- project: `proj_YYYYMMDDHHMMSS_4hex`
- dataset source: `src_YYYYMMDDHHMMSS_4hex`
- dataset version: `ds_YYYYMMDDHHMMSS_4hex`
- run: `run_YYYYMMDDHHMMSS_4hex`
- eval run: `eval_YYYYMMDDHHMMSS_4hex`
- release: `rel_YYYYMMDDHHMMSS_4hex`

### Objective
Create shared foundation utilities.

### Files

# 12. Exact MVP Definition of Done

The MVP is complete when all of the following are true:

1. A user can run:
   ```bash
   moro init demo
   cd demo
   ```

2. A user can import data:
   ```bash
   moro import ./data/raw/support.jsonl --name support
   ```

3. A user can build a dataset:
   ```bash
   moro data build
   ```

4. A user can inspect dataset quality:
   ```bash
   moro data report
   ```

5. A user can check environment:
   ```bash
   moro doctor
   ```

6. A user can get a recipe:
   ```bash
   moro recipe suggest
   ```

7. A user can train:
   ```bash
   moro train
   ```

8. A user can evaluate:
   ```bash
   moro eval run eval/support-golden-v1.yaml
   ```

9. A user can export:
   ```bash
   moro export --format adapter
   ```

10. A user can prepare local deployment:
   ```bash
   moro deploy --target ollama
   ```

11. All state is stored locally.
12. All important failures produce understandable errors.
13. All core schemas are validated by tests.
14. The MVP works on at least one small open model.
15. The codebase is installable via `pip install -e .`
